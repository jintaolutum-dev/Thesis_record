范围：原清单中的 4 种消息大小 × 2 档计算时间 × 10 对 run，共 80 对 midcomm/no_midcomm；统计 MPI backend 的 Case 00–09 和全部 4 种执行策略，共 3,200 个待计算项。Mock backend 不纳入 MPI overlap。

沿用 `analyze_overlap.py` 的 compute overlap 口径：

$$O_r=\frac{\overline{T}_{\mathrm{wait\text{-}recv,no}}-\overline{T}_{\mathrm{wait\text{-}recv,mid}}}{\overline{T}_{\mathrm{mid\text{-}comm,mid}}}\times100\%$$

同一消息大小、同一 case、同一执行策略、同编号 run 配对；分子、分母均取 summary 中的 `average(s)`。分母使用实测计算时间，不直接使用设定 target。汇总为逐 run 百分比的算术平均，而非先平均时间再计算比值。负值与超过 100% 的值原样保留，不裁剪；min/max 表示 run 间范围。

`0.5Tcommunication`、`2Tcommunication` 沿用原清单分组标签；此公式以计算时间为分母，不是通信隐藏比例，2T 组不应直接以 100% 作为理想上限，也不能仅凭该百分比下降断言隐藏的绝对时间减少。

# Comb 实验记录

## 2026-08-10：Intel MPI，2 节点，中等消息，no_midcomm

数据来源：[Comb_09_summary.csv](generated/cm4_inter/intelmpi/2n2r_c24/medium/no_midcomm/Comb_09_summary.csv)。

该实验使用真实 MPI 或 mock 通信，未在 `post-send` 与 `wait-recv` 之间插入 mesh-loop 计算。下表的时间均为 10 次测量的平均值，单位为 ms。

| 通信 | Mesh | Buffers many/few | wait-recv | post-send + wait-recv |
|---|---|---|---:|---:|
| mock | seq | seq / seq | 2.436 | 4.322 |
| mock | omp | seq / seq | 2.133 | 3.983 |
| mock | omp | omp / seq | 2.423 | 4.158 |
| mock | omp | omp / omp | 2.398 | 4.064 |
| mpi | seq | seq / seq | 6.989 | 8.857 |
| mpi | omp | seq / seq | 3.825 | 5.514 |
| mpi | omp | omp / seq | 4.700 | 6.311 |
| mpi | omp | omp / omp | 5.469 | 7.215 |

### 观察

- 真实 MPI 的 `wait-recv` 高于 mock；其中 `mpi + seq mesh + seq buffers` 为 6.989 ms。
- 对真实 MPI，`Mesh omp + Buffers seq/seq` 的 `wait-recv` 最低，为 3.825 ms。
- 不同 OMP buffer 策略的值不单调，说明线程绑定、内存带宽竞争和 `test_all` 轮询开销会影响等待时间。
- 后续比较 overlap 时，应固定同一条 `Comm / Mesh / Buffers` 配置，对照 `no_midcomm` 与 `midcomm` 的 `wait-recv` 和每 cycle 的 `bench-comm` 时间。

## 2026-08-10：三档消息规模的 midcomm 计算时间

固定条件：Intel MPI 2021.16、`2n2r_c24`、`Comb_09`、23 个 OpenMP 线程、`Comm mpi / Mesh omp / Buffers omp/omp`、`wait_recv=test_all`、`wait_send=test_all`。时间为 `mid-comm` mesh-loop 的 10 次测量平均值，单位为 ms。

| 消息规模 | 全局网格 | vars | ghost | mid-comm |
|---|---|---:|---:|---:|
| 小 | `32 x 32 x 32` | 1 | 1 | 0.012251 |
| 中 | `128 x 128 x 128` | 3 | 4 | 0.197932 |
| 大 | `256 x 256 x 256` | 3 | 4 | 2.343094 |

数据来源：[小消息](generated/cm4_inter/intelmpi/2n2r_c24/small_msg/midcomm/Comb_09_summary.csv)、[中消息](generated/cm4_inter/intelmpi/2n2r_c24/medium/midcomm/Comb_09_summary.csv)、[大消息](generated/cm4_inter/intelmpi/2n2r_c24/large/midcomm/Comb_09_summary.csv)。

中消息相对小消息约为 16.2 倍，大消息相对中消息约为 11.8 倍；增长趋势符合 mesh-loop 工作量随本地网格体积增加而增加，但并非严格按体积比缩放，原因包括 OpenMP 调度、缓存与内存带宽效应。

### 实验设置

- 数据范围：`generated/cm4_inter` 下所有完整的 `overlap_metrics.csv`，共 12 份实验组、960 条原始记录。
- MPI：Intel MPI 2021.16.0 与 Open MPI 4.1.8。
- 拓扑：`1n2r_c24` 为 1 节点、2 ranks/node；`2n2r_c24` 为 2 节点、1 rank/node；两者均为 2 个 ranks、每 rank 运行时使用 24 CPUs。
- 消息规模：小为 `32 x 32 x 32`、`vars=1`、`ghost=1`；中为 `128 x 128 x 128`、`vars=3`、`ghost=4`；大为 `256 x 256 x 256`、`vars=3`、`ghost=4`。

## 2026-08-10：全部实验逐条 wait-recv 与 mid-comm 计时

逐条结果见 [逐条计时明细.md](逐条计时明细.md)，按 MPI、拓扑和消息规模分为 12 个表，时间统一为 ms。机器可读的原始索引保存在 [all_waitrecv_midcomm_records.csv](generated/cm4_inter/all_waitrecv_midcomm_records.csv)。两个文件都不对 case、通信后端或 Mesh/Buffer 策略做平均；每一行对应原始 summary 中一个 `Starting test Comm ...` 测试块。

- 实际记录数：943 条。来源为 `cm4_inter` 下 Intel MPI/Open MPI、两种拓扑、三种消息规模的 240 份 `Comb_*_summary.csv`。
- `wait_recv_no_mid_avg_s`：未插入 mesh-loop 时，该测试块的原始 `wait-recv` 平均秒数。
- `wait_recv_mid_avg_s`：插入 mesh-loop 时，同一 case/通信/策略的原始 `wait-recv` 平均秒数。
- `mid_comm_avg_s`：插入 mesh-loop 时，原始 `mid-comm` 单次调用平均秒数；不做 rank 数或 cycle 数折算。
- `mid_comm_samples`：该 `mid-comm` 计时器的样本数，当前记录均为 10。
- `no_midcomm_summary` 与 `midcomm_summary`：两份原始 summary 的相对路径，可直接回溯每个值。

理论上 240 份 summary 每份应有 8 个通信测试块，即 960 条；实际只有 943 条完整配对记录，因为 17 个测试块未在原始 summary 中完整输出。该 CSV 只保留真实存在且同时具备两种模式 `wait-recv` 与 `mid-comm` 的记录，不以均值或零值填补缺失项。

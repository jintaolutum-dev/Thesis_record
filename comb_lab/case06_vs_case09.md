# Case 06 与 Case 09 对比

范围：`cm4_inter / 2n2r_c24`，四种 MPI。严格使用《消息大小影响.md》开头表格指定的可统计 run，共 225 组配对 run、19 个消息点。未加入其他 run。

Case 06 为 `wait_recv=wait_all, wait_send=wait_all`；Case 09 为 `wait_recv=test_all, wait_send=test_all`。两者配置均开启 async，OMP 线程数为 23。已核对所有读取的 summary 中等待方法和 OMP 线程数。该对照反映收发两侧等待策略的共同变化，不能单独归因于 wait_recv。

每个 run 的 overlap = (no_midcomm wait-recv average - midcomm wait-recv average) / mid-comm average × 100%。先按 run 计算，再取算术平均；未将不同消息大小或执行策略混合平均。原始 wait-recv 包含 unpack 等开销，此处不做 MPI - Mock。

差值为 Case 09 - Case 06，单位为百分点（pp）；范围是同编号 run 配对差值的 min 至 max，不是置信区间。总耗时变化为各 run 的 (Case09 midcomm bench-comm max / Case06 midcomm bench-comm max - 1) × 100% 的均值，负数表示 Case 09 更快。实际计算时间及两种模式的等待时间见 CSV。

## 主要观察（seq/seq/seq）

- test_all 没有一致优势。OpenMPI 的 overlap 均值在 9/19 个消息点上升，Intel MPI 为 6/19，Intel MPI TCP 为 9/19，MPICH 为 12/19。这些计数不代表统计显著性。
- OpenMPI 在 578 KiB 和 1.13 MiB 的 overlap 分别提高 35.07 和 21.00 pp，所选 run 的配对差值均为正；midcomm 总耗时分别下降约 1.98% 和 5.72%。在 72.25、144.50、289 KiB 则各 run 的 overlap 都下降。
- MPICH 在 1.56 和 3.12 KiB 的 overlap 分别提高 9.70 和 13.17 pp，各 run 方向一致；总耗时分别下降约 7.32% 和 1.97%。4.52 MiB 则下降 14.39 pp，总耗时增加约 2.68%。
- Intel MPI 在 13/19 个点的 overlap 均值下降，但多数总耗时差异较小。4.52 MiB 的 overlap 下降 20.34 pp，总耗时仅增加约 0.43%，说明 overlap 指标差异不能直接解释成同幅度的性能变化。
- Intel MPI TCP 的改善与退化交替出现，没有随消息大小单调变化的趋势。

## 判读限制

- 18.06 KiB 的 OpenMPI 只有 2 个 run，Intel MPI 只有 1 个，其余各点为 3 个。单个 run 不能反映 run 间波动。
- overlap 小于 0% 或超过 100% 的值原样保留；不能据此声称获得了超出计算时长的物理重叠。
- 差值范围跨过 0 表示不同 run 的变化方向不一致；即使没有跨 0，少量重复也不等于统计显著。
- 总耗时直接对比也会受实际 mid-comm 时间波动影响。CSV 同时提供实际计算时间及 overall overlap gain，支持进一步核对。

Compute Time and Overlap

Compare 0.5T, Tcomm (original configuration) and 2T. Bars show overlap; lines within each message size show hidden Tcomm percentages. Matching colors identify the compute-time group; light bars and hollow markers distinguish the metrics.

Overlap = (mean no_midcomm wait-recv − mean midcomm wait-recv) / mean measured mid-comm time × 100%.
All peaks and negative values are retained. n is the number of valid run pairs for the selected Case; missing values are not counted as zero. 0.5T / Tcomm / 2T retain the experiment group labels.

The denominator is compute time, so a lower percentage does not necessarily mean less absolute communication time is hidden. Lines do not connect different message sizes. Both percentage axes use the same scale. Min–max ranges appear in the table rather than the chart. All three groups are calculated per run from raw timings.

The Tcomm group uses the historical configuration without polling; overlap is recalculated using measured compute time. Actual targets and cycle counts are listed in the data. At 18.06 KiB, the original target is 30 μs, so the 0.5T / 2T targets of 18.5 / 74 μs are not exact multiples of it. Sample sizes and cycle counts may also differ between groups.

Wait-time reduction Δwait = wait-recv without compute − wait-recv with compute. Hidden communication = Δwait / fixed Tcomm. Tcomm is the mean per-run MPI wait-recv minus Mock wait-recv in the original Case 06 without compute. All compute-time groups and Cases share this baseline for the same message size and execution policy. This estimates wait-time reduction; negative values and values above 1 are retained. Missing or non-positive baselines are not plotted.
